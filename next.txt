语音输入/翻译 + 碎碎念扩展方案（草案）
================================

1. 系统目标
-----------
在现有三语文本翻译基础上，增加「语音输入 → 自动识别 → AI 翻译 → 语音播报」链路，并与“对话碎碎念”共用同一套上下文，让 AI 能综合多轮交流的语气、情绪与潜台词，帮助双方跨语言沟通。

2. 语音输入与翻译实现
--------------------
2.1 语音采集
- Android 原生 `SpeechRecognizer`（离线受限、中文/法语准确度一般）；
- **推荐**：第三方 ASR（科大讯飞、火山语音、Azure Speech 等），提供更准确的中/英/法识别 + 噪声鲁棒。
- 集成方式：UI 添加语音按钮 → 录音权限 → 录制 PCM/AMR → 上传 ASR API 得到文字 → 写回当前语言输入框 → 复用现有翻译流程。

2.2 语音播报
- `TextToSpeech`（Android 内建）或第三方 TTS（同 ASR 服务商）。
- 翻译完成后，根据目标语言发音播放，可配置自动/手动播放。

2.3 技术要点
- 录音/播放使用协程或 `LifecycleService` 管理，避免 Activity 重建导致崩溃。
- 大陆部署优先选无 VPN 的 ASR/TTS 供应商；需要备案的可在云端封装代理服务，客户端只与自家 API 交互。

3. 是否需要更换/新增 AI
---------------------
现状：DeepSeek Chat API 支持流式对话，具备一定上下文记忆；碎碎念逻辑已将最近几轮翻译（源语言 + 偏好语言译文）打包给同一个请求，因此 **不强制** 更换模型。

可选增强：
1. **对话长度更长**：DeepSeek 目前摘要只上传最近 8 条，若要更长上下文，可引入自建 RAG（将全部对话摘要/向量存于数据库，摘要时拼接 Top-K 记忆）或换成更大上下文窗口的模型（GPT-4o、Claude 3.5、Gemini 等）。代价是成本增加、国内可用性受限。
2. **多模态能力**：若未来想让 AI 直接接收语音/情绪特征，可选择具备音频输入的模型（例如 DeepSeek-R1 多模态版本、Gemini 1.5 Pro 等）。当前三语文本场景未必需要。

结论：短期内继续使用 DeepSeek 通过 API 实现，无需换模型。只需在上传给 `summarizeConversation` 的数据中纳入语音识别文本（即当前实现已支持）。

4. 上下文记忆与碎碎念可见性
--------------------------
- **API 连续对话记忆**：若调用同一个 `conversation_id`（或在消息数组中附带历史对话），DeepSeek 会在单次调用的数据里看到这些记录；当前实现中我们手动构造了近 8 条的 Prompt，因此 AI **可以**看到碎碎念记录所使用的翻译历史。
- **碎碎念的记录 AI 能看到吗？** 是的，我们把 `ConversationEntry` 中的源文本 + 偏好语言译文发送给 `summarizeConversation`，AI 会基于这些上下文判断说话者语气与潜台词。
- **如果依赖 API 的上下文会丢失怎么办？** 采用「自我持久化」方式，也就是应用将记录保存到本地/服务器，每次请求都把需要的上下文（或摘要）重新放进 Prompt，而不是依赖 AI 提供的会话存储。当前实现就是这样做的。

5. 如果记忆仍不足，怎么强化？
---------------------------
1. **窗口滑动摘要**：将更早的对话定期压缩成摘要，放入 Prompt 顶部，以更小 token 成本保持上下文。
2. **向量检索 (RAG)**：把对话轮次存入向量库，根据当前发言检索最相关的几段，附在 Prompt 中。
3. **多模型协作**：分离“翻译模型”和“情绪理解模型”：翻译仍由 DeepSeek 完成，情绪理解可换用更擅长情感分析的模型（如 GPT-4o-mini）。需新增一个 API Key 与调用链。

6. 落地步骤建议
--------------
1. **第一阶段**：集成语音输入/播报（ASR + TTS），保证文本翻译链路稳定。继续用当前碎碎念机制即可。
2. **第二阶段**：若发现情绪理解不准确，升级 Prompt（已完成第一版）或增加摘要条数；观察 DeepSeek 对上下文响应的质量。
3. **第三阶段（可选）**：若需更深层记忆，引入 RAG/多模型方案，或选用更强的 API（GPT-4o、Claude 3.5 等）。此时需评估成本、合规及网络条件。

当前阻塞：语音接口选型、录音权限与后台服务设计、以及 UI/UX（例如语言切换、长按说话等交互）需进一步讨论确定。*** End Patch
